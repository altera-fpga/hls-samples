# `pipe` Sample

This sample demonstrates how to use the `sycl::ext::altera::experimental::pipe` templated class to configure three different types of pipes available in the HLS IP Gen Compiler.

| Area                 | Description
|:--                   |:--
| What you will learn  | How to use inter-kernel pipes, host pipes with streaming interfaces, and CSR-mapped host pipes
| Time to complete     | 45 minutes
| Category             | Concepts and Functionality

## Purpose

Pipes are constructs that provide communication links between elements of a design. They can take the form of FIFO buffers for streaming data, or register-mapped interfaces for control signals. This tutorial covers all three pipe types through self-contained examples.

## Overview of Pipe Types

Pipes can be categorized along two axes:

1. **By endpoints** — If both the reader and writer are kernels on the same device image generated by the HLS IP Gen compiler, the pipe is an *inter-kernel pipe*. If one endpoint is external to the device image (e.g., a host processor or another IP core), the pipe is a *host pipe*.

2. **By protocol** — Pipes with a streaming protocol (Avalon® ST or AXI ST) are FIFO-based constructs that buffer multiple data elements. Pipes with a memory-mapped protocol (Avalon MM) are register-based and hold a single value at a time.

Inter-kernel pipes always use an Avalon streaming protocol. Host pipes can use either Avalon streaming, AXI streaming, or memory-mapped protocols, depending on your configuration.

| Pipe Type | Endpoints | Protocol | Underlying Storage | Typical Use |
|-----------|-----------|----------|--------------------|-------------|
| Inter-kernel pipe | Kernel to kernel | Streaming (Avalon ST) | On-device FIFO | High-throughput data transfer between concurrent kernels |
| Host pipe (streaming) | External to/from kernel | Streaming (Avalon ST or AXI ST) | FIFO with IP interface | Bulk data streaming into/out of a kernel |
| Host pipe (CSR / memory-mapped) | External to/from kernel | Memory-mapped (Avalon MM) | Single register in CSR | Low-bandwidth control signals and status readbacks |

### Inter-Kernel Pipes

Inter-kernel pipes enable direct kernel-to-kernel communication through on-device FIFO buffers implemented in FPGA memory. Both endpoints (reader and writer) reside on the device, so no external system is involved.

**Use when**: you need low-latency, high-throughput data transfer between two concurrently executing kernels.

See the [inter_kernel](inter_kernel/) example.

### Host Pipes (Streaming)

Streaming host pipes connect a kernel on a device image to the external system (e.g., a host processor or another IP core) through streaming interfaces (Avalon ST or AXI ST). Only one endpoint is inside the the device image where the kernel resides; the other is external. The compiler generates corresponding streaming interface ports on the IP core boundary. With no additional properties specified, a pipe with only one endpoint inside the device image will be a **streaming** host pipe by default, so streaming host pipes are sometimes referred to as just host pipes.

**Use when**: you need to stream bulk data into or out of a kernel at high throughput, with ready/valid flow control.

See the [host_pipes](host_pipes/) example.

### Host Pipes (Memory-Mapped)

Memory-mapped host pipes, also known as CSR pipes, are host pipes configured with the Avalon memory-mapped protocol (`protocol_name::avalon_mm`). Instead of generating a streaming interface, they map the pipe's data and control signals into the kernel's control/status registers (CSR). This provides a register-based mechanism for the host to read or write single values.

**Use when**: you need to send low-bandwidth control signals (configuration parameters, start/stop commands, status readbacks) to or from a running kernel without restarting it.

See the [csr_pipes](csr_pipes/) example.

## Build a Design

> **Note**: When working with the command-line interface (CLI), you should configure the HLS IP Gen Compiler using environment variables. Set up your CLI environment by sourcing the `fpgavars` script located in the root of your HLS IP Gen Compiler installation every time you open a new terminal window.
>
> Linux*:
> - `source <install-dir>/fpgavars.sh`
> - For non-POSIX shells, like csh, use the following command: `bash -c 'source <install-dir>/fpgavars.sh ; exec csh'`

### On Linux*

1. Change to the sample directory.
2. Configure the build system for the Agilex® 7 device family, which is the default.

   ```
   mkdir build
   cd build
   cmake .. -DTYPE=<INTERKERNEL/STREAM/CSR>
   ```

   > **Note**: You can change the default target by using the command:
   >  ```
   >  cmake .. -DFPGA_DEVICE=<FPGA device family or FPGA part number> -DTYPE=<INTERKERNEL/STREAM/CSR>
   >  ```

3. Compile the design. (The provided targets match the recommended development flow.)

   1. Compile for emulation (fast compile time, targets emulated FPGA device).
      ```
      make fpga_emu
      ```
      > **Note**: For the STREAM and CSR examples that use host pipes, make sure that the emulator pipe depth behaviour is as intended. Set the environment variable `CL_CONFIG_CHANNEL_DEPTH_EMULATION_MODE` to `ignore-depth` so that multiple writes can happen to the pipe without first having the contents read.

   2. Compile for simulation (fast compile time, targets simulator FPGA device).
      ```
      make fpga_sim
      ```

   3. Generate HTML performance report.
      ```
      make report
      ```

   4. Compile with Quartus place and route (longer compile time, accurate area estimate).
      ```
      make fpga
      ```

## Run the Design

### On Linux

1. Run the sample on the FPGA emulator (the kernel executes on the CPU).
   ```
   ./pipes.fpga_emu
   ```
2. Run the sample on the FPGA simulator.
   ```
   CL_CONTEXT_MPSIM_DEVICE_INTELFPGA=1 ./pipes.fpga_sim
   ```
